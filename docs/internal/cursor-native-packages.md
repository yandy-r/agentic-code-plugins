# Hidden Cursor native packages (YAN-1132)

Target: v6.0.0. These generated packages remain unlisted; there is no root
`.cursor-plugin/marketplace.json`, and the file-copy installer stays the only user-facing
install path.

| Package                              | Generated payload                                                                                                            |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `packages/cursor/ycc`                | `.cursor-plugin/plugin.json`, `skills/`, `agents/`, `commands/` (thin command files, one per user-invocable skill)           |
| `packages/cursor/ycc-rules`          | Manifest and `rules/` generated by the existing Cursor rules transform                                                       |
| `packages/cursor/ycc-mcp`            | Manifest (`mcpServers: ./mcp.json`, `${VAR}` placeholders under `variables`), literal `mcp.json` from `mcp-configs/mcp.json` |
| `packages/cursor/ycc-hooks`          | Manifest, `hooks/hooks.json`, copied executable `herdr-session-start.sh`                                                     |
| `packages/cursor/installer-fallback` | `config/cli-config.json`, byte-identical copy of `ycc/settings/cursor/cli-config.json` for the unchanged file-copy installer |

`ycc/settings/packages.json` owns selection (`runtime == "cursor"`, `status == "included"`,
`mechanism == "native"`), never `listed: false`; unlisted packages still generate. The root
marketplace ships only at the v6 listing flip and is never written here. Canonical sources
are not duplicated: skills/agents/rules reuse the existing Cursor transforms, MCP comes from
`mcp-configs/mcp.json`, hooks from `ycc/settings/cursor/hooks.json` +
`ycc/settings/cursor/herdr-session-start.sh`. Commands derive from public
(user-invocable) skills only, each forwarding `$ARGUMENTS` to the package-local skill.

Every manifest carries `minClientVersions.cursor: 3.24.12` — the tested client floor from
spike YAN-1124 (IDE 3.24.12 / agent 2026.10.14); the spike establishes no older minimum.
Manifests validate against the vendored official [`cursor/plugins`](https://github.com/cursor/plugins)
plugin schema. Both plugin and marketplace schemas are pinned at commit
`f713f14203cd6420cec13cd7c55c32d598dbab68`, vendored verbatim under the upstream MIT
license (attribution and source paths: `scripts/vendor/cursor/NOTICE`).

## Maintainer checks

```bash
./scripts/sync.sh --only cursor
./scripts/validate.sh --only cursor,cursor-native,packages
./scripts/generate-cursor-packages.sh --check
python3 scripts/test_generate_cursor_packages.py
```

The generator (`scripts/generate_cursor_packages.py`, via
`scripts/generate-cursor-packages.sh`) also supports `--check` (read-only
missing/content/extra/executable drift check) and `--dry-run`. It owns the modeled native
Cursor package roots plus the retired legacy `.cursor-plugin/{skills,agents,rules,config}`
directories, and rejects managed symlinks before writing. `--check` also fails if a root
`.cursor-plugin/marketplace.json` appears before the listing flip. Edit source
configuration or the generator, never generated files.

The validation command above also runs offline native-policy fixtures and package-model/tree/catalog parity, which fails on modeled components that are missing and on recognized components present but unmodeled. It does not prove installed-plugin runtime behavior.

The generator fails before any destination mutation on: unsupported component sets,
unknown hook events (only `sessionStart` is allowed; a mixed or misspelled event name
silences the whole `hooks.json`), credential-shaped secret literals (use `${VAR}`
placeholders), or a missing version.

Native `init` resolves agents and MCP selection resources within the package. Its
MCP helper merges selected servers into project `.cursor/mcp.json`, preserving
unrelated keys and refusing conflicting servers unless explicitly forced. Bare
plugin `${VAR}` references become standalone `${env:VAR}` references without
reading credentials. The file-copy installer projects the original init content
back into installed skills; it does not copy native-only `resources/`.

## Observed verification

- Cursor agent `2026.10.14-941492e` loaded the generated hook package with
  `--plugin-dir`: its `sessionStart` hook sent a session identity report to a
  disposable herdr Unix socket. Existing user hooks were left untouched.
- The 22 native generator tests cover credential rejection, resource containment,
  MCP merge/conflict behavior, standalone interpolation, and installer projection.
- Baseline/current installs into the same disposable HOME preserved config and
  ownership state. Payload differences were the four intentionally updated source
  helpers/reference files; native commands, hooks, and resources were not installed.
- The release version checker accepts the generated manifests at product version
  5.3.0. This preparation does not bump the product to 6.0.0.

## Gates and known limits

Native listing/install is **not** available: all packages are unlisted, there is no root
marketplace, and interactive installed-plugin runtime verification remains the gate.

Known limitation (pre-existing, preserved for file-copy parity): in the generated Cursor
bundle, `skills/_shared/scripts/report-bundle-drift.sh` and
`skills/hooks-workflow/scripts/build-hook-config.sh` auto-discover the repository root by
walking up for a repo-root `.cursor-plugin/marketplace.json`, which this repository does
not ship. Auto-discovery fails and both scripts exit 2; pass `--repo-root` (drift
reporter) or run from the `ycc` source tree instead. Nothing else in the Cursor package
depends on this sentinel.

The file-copy installer is unchanged: `install.sh install --target cursor` still
generates, validates, and rsyncs into `~/.cursor/`; its `commands`,
`hooks`, and `plugins` intents remain no-ops. `WorktreeCreate` and other Claude hook
events are never re-encoded in Cursor packages.
