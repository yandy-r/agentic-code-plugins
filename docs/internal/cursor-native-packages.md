# Cursor native packages (YAN-1132)

Target: v6.0.0. These generated packages are listed by the root
`.cursor-plugin/marketplace.json`; the file-copy installer remains the fallback route.
Install guide: [Cursor native packages](../install/v6/cursor.md).

| Package                              | Generated payload                                                                                                            |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `packages/cursor/ycc`                | `.cursor-plugin/plugin.json`, `skills/`, `agents/`, `commands/` (thin command files, one per user-invocable skill)           |
| `packages/cursor/ycc-rules`          | Manifest and `rules/` generated by the existing Cursor rules transform                                                       |
| `packages/cursor/ycc-mcp`            | Manifest (`mcpServers: ./mcp.json`, `${VAR}` placeholders under `variables`), literal `mcp.json` from `mcp-configs/mcp.json` |
| `packages/cursor/ycc-hooks`          | Manifest, `hooks/hooks.json`, copied executable `herdr-session-start.sh`                                                     |
| `packages/cursor/installer-fallback` | `config/cli-config.json`, byte-identical copy of `ycc/settings/cursor/cli-config.json` for the file-copy installer           |

`ycc/settings/packages.json` owns selection (`runtime == "cursor"`, `status == "included"`,
`mechanism == "native"`), independently of `listed`. The generator writes the root
`.cursor-plugin/marketplace.json` containing exactly the packages with `listed: true`
(all four native packages since the v6 listing flip). Canonical sources
are not duplicated: skills/agents/rules reuse the existing Cursor transforms, MCP comes from
`mcp-configs/mcp.json`, hooks from `ycc/settings/cursor/hooks.json` +
`ycc/settings/cursor/herdr-session-start.sh`. Commands derive from public
(user-invocable) skills only, each forwarding `$ARGUMENTS` to the package-local skill.
The user-file carrier rewrites that skill reference to the absolute installed
`~/.cursor/skills/<name>/SKILL.md` path; it does not depend on plugin activation.

Every manifest carries `minClientVersions.cursor: 3.24.12` — the tested client floor from
spike YAN-1124 (IDE 3.24.12 / agent 2026.10.14); the spike establishes no older minimum.
Manifests validate against the vendored official [`cursor/plugins`](https://github.com/cursor/plugins)
plugin schema. Both plugin and marketplace schemas are pinned at commit
`f713f14203cd6420cec13cd7c55c32d598dbab68`, vendored verbatim under the upstream MIT
license (attribution and source paths: `scripts/vendor/cursor/NOTICE`).

## Maintainer checks

```bash
./scripts/sync.sh --only cursor
./scripts/validate.sh --only cursor,cursor-native,packages
./scripts/generate-cursor-packages.sh --check
python3 scripts/test_generate_cursor_packages.py
```

For an authenticated, opt-in live user-carrier smoke (not part of CI):

```bash
python3 scripts/cursor_live_smoke.py --keep
```

This uses disposable `HOME`/`XDG_CONFIG_HOME`, copies only Cursor authentication
into the lab without printing it, and deletes the copied credential even with
`--keep`. It invokes the real `ycc` and `ycc-hooks` package installer routes with
`YCC_INSTALL_SKIP_BUILD=1`, so it exercises delivery of existing generated
artifacts, not regeneration or validation. It then performs real model inference
and checks foreign command/hook preservation. An authenticated `cursor-agent`
is required; use `--agent <path>` to choose a binary.

The generator (`scripts/generate_cursor_packages.py`, via
`scripts/generate-cursor-packages.sh`) also supports `--check` (read-only
missing/content/extra/executable drift check) and `--dry-run`. It owns the modeled native
Cursor package roots plus the retired legacy `.cursor-plugin/{skills,agents,rules,config}`
directories, and rejects managed symlinks before writing. `--check` also fails if the root
`.cursor-plugin/marketplace.json` is missing or differs from the catalog of listed packages. Edit source
configuration or the generator, never generated files.

The validation command above also runs offline native-policy fixtures and package-model/tree/catalog parity, which fails on modeled components that are missing and on recognized components present but unmodeled. It does not prove installed-plugin runtime behavior.

The generator fails before any destination mutation on: unsupported component sets,
unknown hook events (only `sessionStart` is allowed; a mixed or misspelled event name
silences the whole `hooks.json`), credential-shaped secret literals (use `${VAR}`
placeholders), or a missing version.

Native `init` resolves agents and MCP selection resources within the package. Its
MCP helper merges selected servers into project `.cursor/mcp.json`, preserving
unrelated keys and refusing conflicting servers unless explicitly forced. Bare
plugin `${VAR}` references become standalone `${env:VAR}` references without
reading credentials. The file-copy installer projects the original init content
back into installed skills; it does not copy native-only `resources/`.

## Gates and known limits

Native listing/install is available: all four packages are listed in the root
`.cursor-plugin/marketplace.json`, and installation is interactive (`/plugins`); the
agent CLI has no non-interactive `plugin install`.

Known limitation: `skills/_shared/scripts/report-bundle-drift.sh` and
`skills/hooks-workflow/scripts/build-hook-config.sh` require canonical sources
that installed native and file-copy bundles do not contain. Run them from a
source checkout or pass `--repo-root=/path/to/checkout`. No marketplace manifest
is needed for checkout discovery.

The file-copy installer delivers user commands for `ycc` (`base,commands,settings`)
and user hooks for `ycc-hooks` (`settings,hooks`); `ycc-mcp` selects
`settings,mcp` and `ycc-rules` selects `base` (rules unit) plus `settings`.
These are filesystem carriers, not native account installation. Valid Cursor
steps are `base,skills,agents,commands,settings,rules,mcp,hooks`; default `base`
remains skills/agents/rules. `plugins` remains a no-op. Command wrappers and the
hook script are owned per entry in `installed-units.json`; hook registration is
owned in `managed-config-state.json` via list-union on `hooks.sessionStart`.
`WorktreeCreate` and other Claude hook events are never re-encoded in Cursor
packages or the file-copy carrier. The optional fallback `hooks` component uses
the same user-hook carrier; the settings-only `cli-config.json` does not
register hooks.
