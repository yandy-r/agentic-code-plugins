## Upgrade Notes

### Breaking

- **Codex MCP moved to `ycc-mcp`.** The Codex `ycc` plugin no longer ships `.mcp.json`
  or declares `mcpServers`. Install `ycc-mcp@ycc` to keep the MCP servers.
- **Codex marketplace renamed.** `.agents/plugins/marketplace.json` is now the `ycc`
  catalog with local sources at `./.codex-plugin/ycc` and `./.codex-plugin/ycc-mcp`.
  It replaces the `local-ycc-plugins` catalog and its `./plugins/ycc` source, so
  `ycc@local-ycc-plugins` installs must move to `ycc@ycc` and `ycc-mcp@ycc`.
- **Cursor native layout.** Native Cursor packages live under `packages/cursor/`
  and are listed in a root `.cursor-plugin/marketplace.json`.
- **Codex skill paths.** Helper paths in the Codex `ycc` bundle now resolve relative
  to each `SKILL.md` instead of `~/.codex/plugins/ycc/`.

### Upgrade steps

Preview each migration first, then apply it:

```bash
./install.sh migrate --target claude
./install.sh migrate --target claude --apply
./install.sh migrate --target codex
./install.sh migrate --target codex --apply
./install.sh migrate --target cursor
./install.sh migrate --target cursor --apply
```

- **Claude:** `ycc-hooks@ycc` needs Claude Code 2.1.300 or later. Migration prunes
  installer hooks only after `ycc-hooks@ycc` is enabled, and installer MCP entries
  only after `ycc-mcp@ycc` is enabled; `ycc-all@ycc` alone proves neither.
- **Codex:** migration registers the `ycc` catalog and installs `ycc` and `ycc-mcp`
  before it retires the legacy entry. `~/.codex/agents/` is preserved.
- **Cursor:** migration removes only byte-identical installer copies and prints the
  interactive `/add-plugin` step.
- **opencode and `agents`:** no change; file copy stays the supported install.
