# Release 5.3.0 — 2026-10-15

## Summary

ycc moves skill-managed worktrees to per-runtime, repo-local roots (`.claude/`, `.codex/`, `.cursor/`, `.opencode/worktrees/`), makes `AGENTS.md` the canonical rules file emitted by `ycc:init`, and retires the `ycc/commands/` wrapper layer in favor of native skill invocations. Validators gain a practices ratchet plus `.claude/rules` frontmatter and root-import budget checks, maintainer and destructive workflows are marked user-invocation-only, and a large maintenance pass splits oversized skills into lazy references.

## Upgrade Notes

No breaking changes to skill or agent names. Plugin-based installs need no action; standalone and repo-local installs have the follow-ups below.

- **Wrapper commands retired (#232).** `ycc/commands/` no longer exists; public skills are the native slash invocations (`/ycc:<skill>` on Claude). Invocation is unchanged for plugin installs. Standalone Claude installs that previously wrote wrappers to `~/.claude/commands` are cleaned up on the next skills install: re-run `./install.sh sync --target claude --intent skills` (alias: `--intent commands`). Only wrappers recorded in `~/.config/ycc/installed-units.json` are removed; your own files in `~/.claude/commands` are never touched. opencode keeps one generated command per public skill (`~/.config/opencode/commands/`); re-sync to refresh it: `./install.sh sync --target opencode --intent skills,commands`. Update any scripts or docs that reference `ycc/commands/*.md` paths.
- **Worktree roots moved (#277).** Skill-managed worktrees are now created inside the repository under a per-runtime root: `.claude/worktrees/` (Claude), `.opencode/worktrees/` (opencode), `.codex/worktrees/` (Codex), `.cursor/worktrees/` (Cursor); the cross-tool `agents` bundle auto-detects its runtime and falls back to `.agents/worktrees/`. The former roots (`~/.claude-worktrees/`, `<repo>/.config/opencode/worktrees/`) are retired: existing worktrees there are **not** migrated or removed and keep working, but new runs use the new roots. Add the root for each runtime you use to `.gitignore` (e.g. `.claude/worktrees/`, `.opencode/worktrees/`) before committing, and clean up old worktrees with `git worktree list` / `git worktree remove <path>`. Set `YCC_WORKTREE_ROOT` to override the root explicitly. The Claude worktree-create hook now defaults to `<repo-root>/.claude/worktrees`; native harness worktrees (opencode tools, Codex, Cursor) keep their own placement.
- **`AGENTS.md` is the canonical rules file (#263, #266, #269).** `ycc:init` and `ycc:release-model` now emit and target `AGENTS.md`, with `CLAUDE.md` as a thin importer (`@AGENTS.md`). Repos with legacy layouts keep working; run `/ycc:init --migrate-rules --dry-run` (then `/ycc:init --migrate-rules`) to move an existing long `CLAUDE.md` into `AGENTS.md`. Shipped user-global rules were slimmed to a tool-neutral ruleset and Cursor rules were pruned and scoped, so re-sync rules after upgrading: `./install.sh sync --target <claude|cursor|codex|opencode> --intent rules`. Repositories that adopt the new validators need `paths:` frontmatter on every `.claude/rules/*.md` file and a single standalone `@AGENTS.md` import in `CLAUDE.md` (#276).
- **Maintainer/destructive skills are manual-only (#234).** `backport`, `blueprint`, `bundle-author`, `bundle-release`, `clean`, `compatibility-audit`, `git-cleanup`, `hooks-workflow` and `releaser` now carry `disable-model-invocation: true` (Codex: `allow_implicit_invocation: false`; opencode: `autoinvoke: 'false'`). They remain user-invocable but models will no longer select them automatically. Re-sync skills to pick this up.
- **GitHub MCP default changed (1e52cf66, cc197a6e).** The default GitHub MCP entry moves from the deprecated npm package / PAT remote to the native `github-mcp-server stdio` binary (browser OAuth). `ycc sync --intent mcp` migrates recognized legacy entries; custom GitHub setups are preserved unless `--force`. Install the `github-mcp-server` binary and complete the OAuth prompt on first use. An inherited `GITHUB_PERSONAL_ACCESS_TOKEN` or `GITHUB_API_TOKEN` overrides browser OAuth; unset it to use OAuth. The repository's project-local `.mcp.json` was removed (not part of the shipped bundle).
- **Skill/agent maintenance.** Many oversized skills were split into lazy references and trigger descriptions were shortened/sharpened; the git-cleanup agent is now read-only and agent frontmatter/tool scopes were cleaned. No renames or removals.
