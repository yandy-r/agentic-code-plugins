# YAN-1167 — Generate OMP skills, shared resources and invocation policies

- **Linear:** YAN-1167 (P-YAN-21, M1). **GitHub:** #375. **Target release:** v6.1.0.
- **Contract:** [ADR 0002](../../internal/adr/0002-omp-runtime-contract.md), spike §1.3, §2.8, §3.
- **Base:** `main` (RELEASING.md, trunk-only, tracker `none`).

## Acceptance criteria (from Linear)

1. Inventory parity: every source skill and closure dependency is generated exactly once.
2. A golden test covers path rewriting, executable helpers, manual-only skills, and
   missing-reference failures.
3. Source changes live in `ycc/` or generators; no hand-edited generated bundle.
4. `./scripts/sync.sh` and `./scripts/validate.sh` pass.

## Verified runtime facts (omp 18.12.2, probed live during research)

| Fact                                                                                                                                                                                                                                                         | Evidence                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| Plugin `skills/<n>/SKILL.md` load natively; plugin skills are unprefixed (`/skill:<n>`)                                                                                                                                                                      | spike §1.3; live probe                                                |
| `${CLAUDE_PLUGIN_ROOT}` is not expanded in skill bodies                                                                                                                                                                                                      | spike §2.8                                                            |
| `skill://<n>/<rel>` rejects `..`, so `_shared` is unreachable from another skill by URL                                                                                                                                                                      | `docs/skills.md` (upstream)                                           |
| A `skills/_shared/SKILL.md` with `name: ycc-shared`, `hide: true`, `disable-model-invocation: true` registers `skill:ycc-shared`, and it is **absent** from the prompt skill listing                                                                         | live `--plugin-dir` RPC probe (`get_available_commands`, `get_state`) |
| `disable-model-invocation` normalizes to `disableModelInvocation` (hidden from listing, still `/skill:` invocable)                                                                                                                                           | spike §2.8                                                            |
| `allowed-tools` and `argument-hint` carry no semantics                                                                                                                                                                                                       | spike §2.8                                                            |
| The agent `bash` tool resolves `skill://` paths in arguments, `source`/`.`, quoted args and `$(…)`, and hands the child the physical path (so `BASH_SOURCE`-relative lookups work); nested `bash -c` strings and child scripts do **not** resolve `skill://` | live probe in an omp session                                          |

## Design decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Output to `packages/omp/ycc/skills/` (mirrors `packages/cursor/ycc/skills/`). Do **not** create `.omp-plugin/`.                                                                                                                                                                                                                                                                                                                                                                                                                                                         | `.omp-plugin/` + catalog + `plugin.json`/`package.json` are YAN-1171; audit OM1 fails if `.omp-plugin/` exists while `INSTALL_PATH:omp=unsupported`.                                                                                               |
| D2  | Keep one `skills/_shared/` copy and add a generated hidden stub `skills/_shared/SKILL.md` (`name: ycc-shared`, description, `hide: true`, `disable-model-invocation: true`).                                                                                                                                                                                                                                                                                                                                                                                            | Exactly-once closure (AC1); reachable as `skill://ycc-shared/...`; hidden from the model listing (verified). Vendoring `_shared` into each skill would duplicate ~450 KB 49 times. The `ycc-` prefix avoids collisions with other plugins' skills. |
| D3  | Markdown/text rewrite: `${CLAUDE_PLUGIN_ROOT}/skills/_shared/<rest>` → `skill://ycc-shared/<rest>`; `${CLAUDE_PLUGIN_ROOT}/skills/<skill>/<rest>` → `skill://<skill>/<rest>`; source-relative Markdown links `(../)+_shared/<rest>` → `skill://ycc-shared/<rest>`.                                                                                                                                                                                                                                                                                                      | Native OMP addressing; works in `read` and the agent `bash` tool.                                                                                                                                                                                  |
| D4  | Script files (`.sh`, `.py`, …) keep their `BASH_SOURCE`/`__file__`-relative lookups (layout preserved). A `${CLAUDE_PLUGIN_ROOT}` fallback assignment in a script is rewritten to the same relative path as its primary (Codex precedent); comment-only mentions become `skill://` form.                                                                                                                                                                                                                                                                                | Child processes cannot resolve `skill://`; OMP sets no plugin-root env for skills.                                                                                                                                                                 |
| D5  | `/ycc:<skill>` → `/skill:<skill>`. `subagent_type` / "`ycc:<x>` agent" contexts → bare agent name `<x>` (agent naming is finalized by YAN-1169). Other bare `ycc:<skill>` → `/skill:<skill>`; bare `ycc:<agent-only>` → `<agent>`. Protected `<!-- ycc:verbatim-block -->` regions and the marker itself are untouched.                                                                                                                                                                                                                                                 | OMP has no `ycc:` skill namespace (ADR 0002 §Namespace). `git-cleanup` and `releaser` are both skill and agent, so context decides.                                                                                                                |
| D6  | Fail generation on: `/ycc:<x>` or `ycc:<x>` naming neither a skill nor an agent (outside protected blocks and the marker); a non-glob `${CLAUDE_PLUGIN_ROOT}/skills/<path>` that does not exist in the source; a residual `CLAUDE_PLUGIN_ROOT` in a transformed non-verbatim Markdown file; a non-boolean `disable-model-invocation`.                                                                                                                                                                                                                                   | AC2 "missing-reference failures"; prevents silent dead links.                                                                                                                                                                                      |
| D7  | Frontmatter: keep `name`, `description`, `argument-hint`, `disable-model-invocation`; drop `allowed-tools` (no OMP semantics; carries Claude tool IDs and `${CLAUDE_PLUGIN_ROOT}` globs).                                                                                                                                                                                                                                                                                                                                                                               | Spike §2.8; keeps manual-only policy (9 skills) native.                                                                                                                                                                                            |
| D8  | Tool-identifier wording: map unambiguous Claude tool names to OMP tools in prose (`AskUserQuestion` → `ask`, `WebSearch` → `web_search`, `WebFetch` → `read` on the URL, `TodoWrite`/`TaskCreate`/`TaskUpdate`/`TaskList`/`TaskGet` → `todo`, "Task tool"/"Agent tool" → `task` tool). `_shared/references/agent-team-dispatch.md` becomes a short "agent teams (`--team`) are unsupported on OMP; rerun without `--team`" note (Cursor precedent). Deeper workflow semantics (worktree roots, background jobs, questions in non-interactive modes) stay with YAN-1170. | Scope boundary with YAN-1170.                                                                                                                                                                                                                      |
| D9  | Reuse `VERBATIM_SKILL_FILES` (multi-target files copied byte-for-byte) from `generate_codex_common.py`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Same reason as Codex/Cursor: those files describe every target literally.                                                                                                                                                                          |
| D10 | Preserve source file modes (executable helpers stay executable); prune orphans; `--check` mode compares the tree byte-for-byte and mode-for-mode.                                                                                                                                                                                                                                                                                                                                                                                                                       | AC2 executable helpers; drift detection.                                                                                                                                                                                                           |
| D11 | Wire `omp` into `sync.sh` (target `omp`) and `validate.sh` (target `omp`: `--check`, content policy, golden tests), `scripts/lib/validate-scope.sh` (`packages/omp/*` and the new scripts → `omp`; `ycc/*` also selects `omp`), the scope tests, `.prettierignore`/`excludes.sh` (`packages/omp`), and `pyproject.toml` mypy `files`. YAN-1171 later extends the `omp` scope with the catalog and package tree.                                                                                                                                                         | Required by AGENTS.md Testing Changes; new Python modules join `mypy --strict`.                                                                                                                                                                    |
| D12 | Flip matrix `SKILLS:omp` to `partial` with a note: generated tree exists and loads via `--plugin-dir`; not installable until YAN-1171/1172; workflow semantics YAN-1170. Leave `INSTALL_PATH:omp` `unsupported`. Remove the satisfied YAN-1167 gate from the `ycc`/`omp` row of `ycc/settings/packages.json` only if validators accept it.                                                                                                                                                                                                                              | Matrix/tree must agree; never claim full parity without an install path.                                                                                                                                                                           |

## Tasks

1. `scripts/generate_omp_skills.py` (+ `scripts/generate-omp-skills.sh` wrapper): D1–D10. Typed, `mypy --strict` clean. Reuse helpers from `generate_codex_common.py` (`parse_frontmatter`, `model_invocation_disabled`, `protect_marked_verbatim_blocks`, `restore_marked_verbatim_blocks`, `fix_mcp_malformed_tokens`, `VERBATIM_SKILL_FILES`, agent alias loading) rather than copying them.
2. `scripts/test_generate_omp_skills.py` (unittest, golden): path rewriting (shared, sibling skill, Markdown relative links, script fallback), `/ycc:` and bare `ycc:` mapping incl. the skill+agent overlap, protected blocks untouched, executable bit preserved, manual-only skills keep `disable-model-invocation: true` and `allowed-tools` is dropped, `_shared/SKILL.md` stub shape, exactly-once inventory parity against `ycc/skills`, and each D6 failure raising.
3. `scripts/validate-omp-skills.sh`: `--check` + content policy (no `CLAUDE_PLUGIN_ROOT`, `/ycc:`, `\bycc:` outside verbatim files/blocks).
4. Wiring per D11; matrix/packages per D12; regenerate with `./scripts/sync.sh`.
5. Live smoke: build a throwaway plugin root (`.omp-plugin/plugin.json` + symlinked `packages/omp/ycc/skills`) in a temp dir, run `omp --mode rpc --plugin-dir` with the null provider (pattern from `scripts/test-omp-runtime-contract-spike.sh`), confirm all 49 `skill:<name>` commands plus `skill:ycc-shared`, the 9 manual-only skills and `ycc-shared` absent from the prompt listing, and no load warnings.
