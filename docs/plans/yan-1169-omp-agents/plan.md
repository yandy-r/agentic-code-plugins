# YAN-1169 — OMP agents and delegation

Linear YAN-1169 · GitHub #381 · Target release: ystack v6.1.0 (next minor).

## Acceptance criteria (from the issue)

1. Every agent in `ycc/agents/` is discoverable and invokable as an OMP task agent.
2. Planning, review, implementation, research, orchestration and fan-out workflows run with real
   delegated agents.
3. Unsupported fields fail validation; nothing is silently dropped.

## Contract (omp v18.12.3 source, `docs/task-agent-discovery.md`, ADR 0002 §2.6)

- Frontmatter: `name`, `description` required; `tools` (CSV or list), `model` (`@role` aliases).
  OMP ignores unknown keys, so the generator, not OMP, must reject them.
- `tools` names are canonicalized to built-ins (`read`, `bash`, `edit`, `write`, `grep`, `glob`,
  `web_search`, `task`, …); any other name is filtered out without a warning. MCP tools are always
  additive to the child session, so `mcp__*` entries never need listing.
- `model:` is dropped only for Claude-dialect roots: a `.claude-plugin/plugin.json` with no
  `.omp-plugin/plugin.json` (`pluginUsesClaudeModelDialect`). The manifest-less `packages/omp/ycc`
  tree under `--plugin-dir` and an `.omp-plugin` root (generated by YAN-1171) both keep it; this
  issue's live check builds a throwaway `.omp-plugin` root.
- `@task` inherits the session model; `@slow` resolves through `modelRoles.slow`, then the built-in
  slow priority chain. Omitted `model` uses the parent model.

## Decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                          | Why                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | New `scripts/generate_omp_agents.py` writes `packages/omp/ycc/agents/<stem>.md`; `--check` byte-compares and prunes orphans, like the skills generator.                                                                                                                                                                                                                                           | Same package tree as YAN-1167; one convention.                                                                                                                    |
| D2  | Keep `name` and `description` verbatim; keep the source file stem.                                                                                                                                                                                                                                                                                                                                | OMP looks agents up by frontmatter `name` (`turso-database-architect.md` is `sql-database-architect`).                                                            |
| D3  | Explicit tool table: `Read→read`, `Grep→grep`, `Glob→glob`, `Write→write`, `Edit→edit`, `WebSearch→web_search`, `WebFetch→read` (OMP `read` fetches URLs), `NotebookEdit→edit` (OMP edits `.ipynb` cells), `Bash`/`Bash(<scope>)→bash`. `mcp__<server>__<tool>` entries are omitted because OMP mounts MCP tools additively; the server must exist in `ycc-mcp`. Any other tool fails generation. | Upstream silently drops unknown names; the generator must not.                                                                                                    |
| D4  | OMP has no command-scoped shell permission. A scoped `Bash(<cmd>:*)` list becomes `bash` plus a generated `## Shell scope (OMP)` section listing the allowed command prefixes as a hard instruction.                                                                                                                                                                                              | Preserves the read-only/auditor intent instead of silently widening it. Subagents run with `approvalMode: yolo`, so this is prompt-level, and the matrix says so. |
| D5  | `model`: `opus→@slow`, `sonnet→@task`, `inherit` or absent → no `model` key. Any other value fails.                                                                                                                                                                                                                                                                                               | ADR 0002 role mapping; `@task` keeps today's "same as session" behavior, `@slow` is the user-tunable deep-reasoning role.                                         |
| D6  | `color` is dropped (documented OMP no-op). Any frontmatter key other than `name`, `description`, `tools`, `model`, `color` fails generation.                                                                                                                                                                                                                                                      | Criterion 3.                                                                                                                                                      |
| D7  | Bodies reuse the skills generator's rewrites: `${CLAUDE_PLUGIN_ROOT}` paths, `/ycc:`/`ycc:` references through the shared agent/skill catalog, Claude tool wording, verbatim blocks. Unknown references fail.                                                                                                                                                                                     | Single transform implementation.                                                                                                                                  |
| D8  | No `blocking`, `spawns`, `output` or isolation keys are emitted. Delegation semantics are explicit in the capability matrix: OMP `task` runs agents in the background when `async.enabled`, otherwise inline; worktree isolation is the per-call `isolated` flag (`task.isolation.enabled`). Skill-side rewording of `isolation: "worktree"` / `run_in_background` belongs to YAN-1170.           | No ycc agent declares those Claude fields; skill semantics are YAN-1170's scope.                                                                                  |
| D9  | Wiring: `generate-omp-agents.sh`, `validate-omp-agents.sh` (drift + content policy), `sync.sh omp`, `validate.sh omp`, `validate-scope.sh`, `test-validate-scope.sh`, `pyproject.toml` mypy files, CONTRIBUTING. Matrix `AGENTS:omp` → `partial`; drop the YAN-1169 gate from `packages.json`.                                                                                                    | Same pattern as YAN-1167.                                                                                                                                         |

## Tests

`scripts/test_generate_omp_agents.py` (golden): tool mapping incl. scoped Bash section and dedupe,
MCP omission, model mapping incl. inherit, `color` dropped, unknown key / tool / model / MCP server
fail, body namespace rewrite, inventory parity (each source agent once, names unique, `--check`
detects drift).

## Live verification

Throwaway plugin root (`.omp-plugin/plugin.json` + copied `packages/omp/ycc/{agents,skills}`):

1. RPC `get_state` with the null provider lists all 55 agents; a discovery probe reports
   `@slow`/`@task` models kept.
2. Real `omp -p` runs with `--plugin-dir` delegate to ycc agents for planning (`planner`), review
   (`code-reviewer`), implementation (`implementor`, in a scratch git repo), research
   (`code-researcher`) and a two-agent fan-out batch, and return their reports.
