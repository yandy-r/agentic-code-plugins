# Security Research: codex-native-packages

## Executive Summary

The native split can remain low-risk if generation is deterministic, secrets remain symbolic, hooks remain excluded, and the future catalog is rendered only into an explicitly requested external tree before the v6.0.0 flip. The existing discovered repository catalog already exists: replacing it, renaming it, deleting it, or making its entries empty would change current marketplace discovery, so `listed:false` cannot be implemented by blindly rewriting that file. This is source-based research; no validator, live CLI install, credentialed MCP connection, or new vulnerability scan was run.

## Authentication and Authorization

This feature adds no service, account system, or authentication flow. A Git marketplace controls where executable MCP definitions and model-consumed skills come from; the user authorizes that repository by adding/installing it. A marketplace policy of `{"installation":"AVAILABLE","authentication":"ON_INSTALL"}` is metadata, not proof that every MCP endpoint has authenticated successfully or that hooks are trusted.

Keep repository marketplace generation separate from `scripts/codex_marketplace.py`, whose purpose is merging/removing the user-level `local-ycc-plugins` entry while preserving other plugins and an existing marketplace name (`:55-91,94-106`). The installer uses `HOME/.agents/plugins/marketplace.json` and its current selector (`scripts/lib/install/targets/codex.sh:52-73,130-153,170-187`). The native repo catalog must not overwrite that user-level file, alter user MCP credentials, or register/enable packages during generation.

Hooks remain excluded: the spike records discovered SessionStart hooks as untrusted and did not verify trust grant/dispatch; WorktreeCreate is unsupported (`docs/internal/spikes/codex-marketplace.md:16-18,108-118`). Packaging must not infer authorization from hook discovery, and the acceptance harness must not grant trust or execute hooks.

## Data Protection

- **Source of truth:** `mcp-configs/mcp.json:1-48`. The native MCP-only package should copy this source directly, not a user TOML, generated cache, `.env`, auth file, or legacy installed bundle.
- **Required native representation:** `{"env":{"XERO_CLIENT_SECRET":"${XERO_CLIENT_SECRET}"}}`; secret-bearing placeholders must survive byte-for-byte. Non-secret literal configuration is not automatically forbidden.
- **Separate installer representation:** `generate_codex_mcp.py:41-61` translates same-name placeholders into `env_vars`; this is symbolic pass-through, not a literal secret. Do not replace the native `.mcp.json` format with the installer's `mcp_servers` JSON shape.
- **Current limitations:** the translator preserves ordinary literal env values, forwards remote headers verbatim, and applies overrides wholesale (`generate_codex_mcp.py:54-55,64-93`). Those functions do not prove that source/overrides contain no secrets. The error at `:51` interpolates a rejected env value; new secret checks must not repeat that diagnostic pattern.
- **Checks:** retain exact placeholder references and parity with the authoritative source; reject literal values in known credential fields without printing them. Also inspect any future auth headers, URL user-info/query credentials, and token-like CLI arguments rather than limiting checks to `env`. Do not reject harmless constants such as an operating mode simply because they are literals.
- **Harness retention:** use `umask 077` and temporary locations, sanitize paths, and clean up on EXIT as the existing harness does (`test-codex-marketplace-spike.sh:4,47-58,86-110`). Avoid copying credentials in the first place; output redaction is not a substitute. No new PII collection, retention service, or compliance processing is introduced by deterministic local generation.

## Input Validation

### Local marketplace sources

The candidate native catalog has a fixed shape:

```json
{
  "name": "ycc",
  "plugins": [
    { "name": "ycc", "source": { "source": "local", "path": "./.codex-plugin/ycc" } },
    { "name": "ycc-mcp", "source": { "source": "local", "path": "./.codex-plugin/ycc-mcp" } }
  ]
}
```

Additional existing interface/policy fields may be retained. `listed` must not appear as a runtime catalog field. Paths resolve from the marketplace repository root, not the directory containing the JSON file. Require `./` and reject absolute paths, backslashes/drive prefixes, `..` components, empty targets, and NULs; then verify resolved containment and the expected native manifest. For a fixed generator map, exact equality to the two intended paths is simpler and stronger than accepting arbitrary caller-provided strings. Do not claim upstream symlink/traversal behavior is verified: the prior spike's upstream source links explicitly carry an unverified-source caveat (`docs/internal/spikes/codex-marketplace.md:91-102`).

### External native output

Prefer `--native-output DEST` over generic `--output-dir`: it explicitly selects the gated layout as well as the destination. Resolve DEST against existing ancestors; reject repository root, descendants, ancestors containing the repository, filesystem root, and symlink aliases that violate those rules. Reject symlinked managed parents/leaves before write, copy, chmod, or prune; resolve every expected path inside DEST. Also reject source symlinks escaping authored input roots rather than reading arbitrary local files into a distributable bundle.

Own only the two intended package roots and the single catalog file, not all of DEST or `.codex-plugin`. Never recursively remove DEST. Preserve unrelated sentinel files outside owned paths; define stale owned-file removal explicitly and report unexpected hooks rather than silently deleting potentially user-owned executable configuration. This protects normal developer use; it is not a claim of race-free operation against another process maliciously swapping symlinks during generation.

Use the validated package model (`package_model.py:200-245`) and fixed schema package keys (`packages.schema.json:27-39`) rather than using arbitrary package names as path fragments. Reuse the repository's lexical-plus-resolved containment pattern from evidence validation (`package_model.py:182-197`), adapting it for output directories. No shell command construction is needed to render JSON or copy source files; fixture subprocesses should receive argv arrays/quoted shell arguments.

## Infrastructure Security

The existing harness is a useful starting point, not a complete native package acceptance test: it creates synthetic marker plugins rather than rendering the real source (`test-codex-marketplace-spike.sh:131-169`). A new or extended harness should render the full future tree from authored sources into its isolated fixture and commit that tree locally.

Required controls:

1. Fresh per-case HOME, CODEX_HOME, XDG directories, TMPDIR, and empty work directory outside this checkout; no user config/auth copied.
2. `env -i` with a deliberate PATH; no API tokens, proxies, SSH agent, Node preload settings, or ambient Git environment. Preserve `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, and empty `credential.helper` (`:63-85`). Set fixture `core.hooksPath` to an empty controlled directory if invoking Git commits, so fixture creation cannot dispatch configured hooks.
3. `GIT_ALLOW_PROTOCOL=file` and an exact `.invalid` HTTPS URL-to-local-bare rewrite. Use the fixture's commit SHA in `marketplace add --ref`, not `main`. Never contact GitHub, npm, login endpoints, or remote MCP URLs.
4. For an actual enforced no-network claim, put all exercised processes in a network-disabled namespace/container; `env -i` and file-only Git alone are insufficient. Record the isolation mechanism and fail rather than quietly downgrade a requested strict run.
5. Bound commands with timeout, capture exit codes and sanitized output synchronously, and never start sessions/turns or ask Codex to execute skills/MCP/hook commands.
6. Assert exact marketplace name, both plugin IDs, installed manifests, payload hashes, component segregation, and absence of hooks. Include full checkout, sparse catalog+both payloads, and catalog-only sparse negative control; do not treat listing success as install success.

A Git fixture proves the Git-backed discovery/local-source/cache boundary after URL parsing. It does not prove live public GitHub/fork transport authentication or native MCP runtime environment expansion; label those limitations explicitly, as the prior spike does (`docs/internal/spikes/codex-marketplace.md:113-118`).

## Secure Coding Guidelines

- **Gate first:** while `packages.json:26-43,84-99` records Codex `listed:false`, preserve discovered legacy output. `RELEASING.md:55-61,78-81` requires hidden unfinished work and explicitly retains the legacy Codex entry. Generating an empty new-name catalog is not equivalent to leaving current behavior alone.
- **Native output:** reuse `generate_codex_skills.write_tree(dest_root, dry_run)` for authored skills/shared; do not copy the already-generated legacy tree. Main manifest exposes skills only, MCP manifest exposes MCP only, both use the authoritative lockstep version, and neither includes hooks/agent TOMLs/settings.
- **Model use:** included/native controls eligibility; listed controls production discovery, not whether an explicit isolated candidate can be tested. Keep this distinction out of runtime JSON. Excluded Codex hooks cannot be overridden by a preview option.
- **Safe check/dry-run:** `--native-output DEST --check` should render expected content in a separate temporary tree and compare without mutating DEST. Dry-run must not create directories or prune. Check mode must also catch forbidden/stale owned files, not only missing expected bytes.
- **Lifecycle assertions:** test repo/root/ancestor/symlink destination rejection before mutation; unrelated sentinels survive; repeat generation is deterministic; removed source skills disappear only in owned output; stale main MCP and hook payloads fail native validation.
- **Credential assertions:** inject harmless sentinel env values during pure generation; generated native MCP equals authoritative symbolic input; errors/logs never echo secret-like values. Do not execute native MCP servers to test install acceptance.
- **Legacy regression:** existing `test_codex_marketplace.py:43-73,88-154` checks user-level naming, source shape, merge preservation and removal. Preserve this behavior and add focused native generator tests rather than changing the user's marketplace as a side effect.

## Trade-off Recommendations

1. **Hidden but testable:** explicitly requested external repo-shaped output reconciles real generated-tree install acceptance with the pre-flip gate. Keep default legacy behavior unchanged. Default generation of an unlisted MCP-only artifact is possible, but adds an owned lifecycle surface without improving discovery isolation; external-only split output is the simpler security boundary unless the final spec explicitly requires tracked artifacts.
2. **Do not fix rollout by breaking compatibility:** removing MCP from the shipping main package now changes what existing install.sh snapshots contain, even if the catalog remains unchanged. Perform that split only in the external candidate until the authorized listing/migration flip.
3. **Future model flip:** if automatic listed=true routing is part of this implementation, validate the full intended split before writes and fail on an inconsistent partial-flip state. Listing flags alone do not prove migration/dedupe gates passed; the release PR remains the authorization boundary. Keep production native routing explicit in tests.
4. **No security theater:** commit pins, hashes, sparse checkout, JSON lint and env isolation solve different problems. Preserve all useful controls without describing one as proof of another. Prefer strict egress isolation when “no network” is an acceptance claim; otherwise document the exact limitation.
5. **No unrelated dependency rewrite:** retain inherited MCP commands, auth behavior and installer marketplace identity. Track pinning/hardening separately rather than bundling policy changes into the package split.

## Open Questions

- **Resolved:** the discovered catalog already exists and is tracked, named `local-ycc-plugins`, with source `./plugins/ycc`; no `plugins/` path was found in this worktree. The current payload resolution looks inconsistent with the spike's root-relative rule [INFERENCE], but fixing it would itself change present behavior and is not a reason to bypass the pre-flip gate.
- **Spec decision:** should split package artifacts exist in the repository now, or is a fully generated external native tree the intended unlisted deliverable? The latter best preserves the current combined main payload without duplicate generated skills trees.
- **Acceptance evidence:** does “fork install works” mean the hermetic Git fixture explicitly allowed by the issue, or also live public GitHub transport? Only the former can satisfy an offline/no-network harness; report it precisely.
- **Strict egress prerequisite:** which available namespace/container mechanism should enforce no network in the final acceptance environment? This research did not probe host capabilities or run the harness.
- **Runtime placeholder boundary:** `${ENV}` retention is verified by source inspection, not a credentialed native MCP startup. API research should confirm supported native expansion syntax without providing or logging real secrets.
